# Animaku 多端客户端移植与架构路线图

> 本文档用于指导 Animaku 客户端向 **Android、iOS、Windows 桌面端** 多端移植的技术选型、工程架构设计与实施路线。

---

## 一、 背景与核心诉求

* **平台覆盖**：Android、iOS、Windows 桌面端。
* **质量追求**：非简单套壳，追求**高画质（Anime4K）、高帧率丝滑弹幕（120Hz）、低发热、高质感原生交互与快捷键**。
* **工程节奏**：周期充裕，采用自底向上、模块化打磨路线。

---

## 二、 核心技术选型决策

### 1. 为什么弃用「纯 WebView 套壳」？
| 体验维度 | 纯 WebView 套壳的硬伤 | 原生自绘 / Flutter 的表现 |
| :--- | :--- | :--- |
| **横竖屏旋转** | 依赖 DOM 伪全屏，重力感应切换易伴随画面闪黑、重新排版卡顿 | 系统传感器联动，秒级原生旋转，零卡顿 |
| **播放手势** | 亮度/音量/进度手势容易与系统边缘返回、下拉刷新产生滑动冲突 | 原生手势精准拦截，手感干脆利落 |
| **后台与画中画** | 切后台易被系统节能机制暂停或杀掉进程，PiP 接入脆弱 | 原生挂接系统媒体通知栏、锁屏控件与画中画 |
| **解码与发热** | `hls.js` 依赖 JS 线程解封装，Canvas 弹幕重度发热、中低端机掉帧 | C/C++ 硬件直接解码，GPU 垂直同步自绘，百条弹幕不掉帧 |

### 2. 为什么选择「Flutter + media_kit (libmpv)」？
* **全平台一致的顶级播放内核**：
  * `media_kit` 底层统一基于 **`libmpv`**，硬件直解，全平台行为高度一致。
  * 原生支持自定义 HTTP Headers（Referer、User-Agent、Cookie），无缝支持防盗链源站。
  * **支持原生挂载 Anime4K GLSL 着色器**，在桌面端和手机端实现真正的 GPU 零拷贝超分，性能和画质远超 Web 方案。
* **120Hz 高刷自绘弹幕**：
  * 采用 Flutter `CustomPainter` 在 GPU 帧回调中绘制，脱离 DOM 树限制，高并发弹幕依然流畅。
* **业务与算法无缝移植**：
  * Dart 与 TypeScript 语法和类型系统极其相似，`packages/shared` 下的分集对齐算法、弹幕哈希去重等逻辑几乎可以 1:1 直译为 Dart。

### 3. 代码组织方式：「独立 Git 仓库」
* **不放入主 Monorepo 的原因**：
  * Dart 与 TypeScript 无法跨语言直接 `import` 共享代码，失去了 Monorepo 最核心的收益。
  * 混在同一个仓库会导致 pnpm 与 Flutter SDK/Gradle/CMake 工具链互相干扰，破坏 IDE 智能提示与 Git 历史。
* **协同方式**：
  * 新建独立仓库（如 `animaku-client` 或 `animaku-app`）。
  * 现有服务端作为标准的 RESTful API 提供方，客户端版本发布周期完全解耦。

## 四、 日常开发与调试工作流

在 Flutter 体系下，本地开发效率与 Web 的 `pnpm dev` 相比毫不逊色，且具有更强的状态保持能力：

### 1. 本地极速预览（主开发阵地）
* 运行命令：
  ```bash
  flutter run -d windows
  ```
* **体验**：直接启动原生 Windows 窗口，修改代码按保存（Ctrl + S），**0.3 秒内触发 Stateful Hot Reload（有状态热重载）**，无需重启，当前的播放位置与界面状态完全保留。90% 以上的跨端 UI 和业务逻辑均可在此完成调试。

### 2. 接口联调网络配置
* **Windows 本地运行**：直接访问 `http://127.0.0.1:3000`。
* **Android 模拟器运行**：访问 `http://10.0.2.2:3000`（映射宿主机 localhost）。
* **真机局域网调试**：手机与电脑同 Wi-Fi，访问电脑局域网 IP（`http://192.168.x.x:3000`）。
* **免搭本地环境模式**：直接指向已经部署好的线上服务器 API。

### 3. 一键打包分发
* **Android APK 生成**：
  ```bash
  flutter build apk --release
  ```
  产物位于 `build/app/outputs/flutter-apk/app-release.apk`，直接发送至手机安装即可。
* **Windows 绿色版生成**：
  ```bash
  flutter build windows --release
  ```
  直接将 `build/windows/x64/runner/Release/` 文件夹打压缩包，解压即运行。
* **全自动云端打包（推荐）**：
  在客户端独立仓库配置 GitHub Actions，推送 Git Tag 时，由云端自动化打包各端二进制并发布到 GitHub Releases。
