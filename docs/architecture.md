## 1. 播放引擎与状态机互锁设计

### 1.1 原地 Seek 状态机与 DOM 生命周期解耦
在常规流媒体播放器实现中，切换剧集或恢复历史播放进度常依赖重新挂载播放器 DOM 节点（如递增 `playerKey`）。这种模式会导致：
* **Late Hydrate 历史续播冲突**：历史播放位置在播放器初始化完成前/后注入时序不稳定；
* **DOM 暴力卸载与重建 (Unmount & Remount)**：引发画面黑屏闪烁、GPU 解码器重置以及内存短暂激增。

Animaku 播放器解耦了生命周期键，采用**原地状态机（In-place State Machine）**与 **4 重事件互锁机制**：
* **权威时长决断器**：实时比对 `HTML5VideoElement.duration`、HLS 播放列表时长与历史锚点，消除异步元数据到达延迟；
* **非侵入式原地 Seek**：换集与续播期间保持播放器底座稳定，通过状态锁拦截多余的重置事件，起播达到近 0ms 瞬间响应。

### 1.2 WebKit / Safari 深度兼容优化
针对 Safari 与 iOS WebKit 的特殊机制进行了内核级处理：
* **动态 MIME 提示显式注入**：针对部分第三方片源以 `.mp3` 伪装 1080P MP4 视频直链绕过防盗链的场景，动态构造带 `<source type="video/mp4">` 的虚拟元素，彻底避免 Safari 原生 AVFoundation 将其误判为纯音频流而导致黑屏。
* **50ms 微缓冲存量乐观起播**：消除 MP4 格式起播的门禁双标，规避 WebKit 节能挂起机制导致的 8 秒硬等超时。

### 1.3 WebGPU 实时超分辨率 (Anime4K)
集成 Anime4K WebGPU 计算着色器（Compute Shader），利用客户端图形算力实现实时 2× 纹理重建与线条抗锯齿：
* 提供「效率（Efficiency）/ 平衡（Balanced）/ 质量（Quality）」多档预设；
* 在渲染管线中实时对低清动画番剧（480P/720P/1080P）进行边缘重构，升格至 4K 视觉画质。

## 2. 高精物理时钟弹幕系统

详细基准测试与性能报告见 [弹幕渲染引擎性能报告 (docs/danmaku-perf.md)](./danmaku-perf.md)。

### 2.1 物理时钟与漂移滤波
传统弹幕引擎常依赖定时器（`setInterval` / `requestAnimationFrame` 累加步进），在浏览器降频或高负载丢帧时容易出现速度突变或位置抖动。
* **单调物理时间驱动**：弹幕绝对 X 坐标由 `performance.now()` 单调时钟严格计算；
* **Zero 死区与 EMA 低通滤波器**：在视频播放速率变动、微小卡顿或 Seek 时，采用指数移动平均（EMA）平滑时间轴漂移，彻底杜绝弹幕 1~2px 的横跳与微回弹；
* **7.5s 恒定穿越时长**：切倍速时动态连续相位重定，保持人体视觉舒适的恒定阅读节奏。

### 2.2 硬件帧呈现同步与位图池
* **rVFC (requestVideoFrameCallback)**：优先与底层视频解码器的真实帧渲染时机严格对齐，实现弹幕与画面的像素级帧同步；
* **1:1 Retina 离屏字形位图缓存池**：高频弹幕文本预先栅格化至离屏 Canvas，大幅降低主线程 GC 压力。

## 3. 流水线规则引擎与多源适配架构

详细规范与适配器实战见 [视频源接入规范与专有适配器实战指南 (docs/video-source-integration.md)](./video-source-integration.md)。

### 3.1 流水线算子解释器架构
* **AniBaka (`anx-rule/2`)**：支持 20+ 核心算子组成的 DAG / 顺序流水线（Fetch, Follow, Template, Regex, Replace, Cheerio CSS, JSONPath, BaseN, AES-CBC/GCM, MD5, SHA1/SHA256, MacCMS/ECPlayer 逆向解密）；
* **多源兼容解析**：保持对早期规则模型的底层兼容解析能力；
* **零自动回退代理原则 (Zero Auto Proxy Fallback)**：客户端优先直连源站 CDN，严禁静默回退服务器代理偷跑带宽。

### 3.2 M3U8 智能去广告模型
* 内置多维度切片加权打分模型：结合切片时长方差、域名跨域指纹、序列号不连续性及 `#EXT-X-DISCONTINUITY` 标记，毫秒级识别插播广告切片并切除。

## 4. 番剧推荐引擎与多象限分桶抽样算法

### 4.1 推荐流架构 (WatchRecommendations)
* **Slot 0 系列接续**：优先分析动画关系图谱，顺承推荐续作/剧场版/前作，并带有真实年份与状态补全；
* **国家 Tag 严格优先级约束**：`日本 → 国产 → 欧美 → 韩国` 优先级约束，搭配题材 Tag 交叉验证与多阶容灾采样，彻底消除跨国推荐语义漂移；
* **自适应多象限分桶**：在 6.0~8.5 评分区间建立平衡分桶，兼顾热门佳作与高口碑冷门宝藏番剧。

## 5. 服务端高并发设计、缓存与安全防御

### 5.1 SQLite L1+L2 双层持久化与防击穿
* 基于 SQLite 原生驱动实现搜索结果、剧集列表与详情的高速持久化；
* 配合 **Single-Flight 并发合并机制**，在多客户端同时搜索同一热门番剧时，仅向上游源站发出单次请求，彻底防止缓存击穿与上游封禁。

### 5.2 有效播放统计与微任务合批限流
* **15s 有效播放上报**：客户端播放满 15 秒后触发轻量上报，服务端内存维护 10 分钟滑动窗口原子去重，杜绝刷量；
* **日志合批写入 (`ip_access_logs`)**：借助 Node.js `setImmediate` 将访问统计汇聚到事件循环尾部批量落库，减少 90% 的磁盘 I/O 消耗；
* **滑动窗口频控**：为基础 API 与重型爬虫端点配置多档频率限制，防范 DDoS 与恶意高频扫描。

## 6. 全栈路由预加载与边缘 CDN 缓存

* **意图预取 (Intent-based Preload)**：鼠标悬停在卡片或选集方块时，前端主动触发轻量 `preloadRoute` 与播放器资源预热；
* **Cloudflare Anycast 边缘缓存**：推荐与热门榜单端点下发 `s-maxage=86400` 与 `Cloudflare-CDN-Cache-Control`，实现全球毫秒级静态边缘分发（详见 [Cloudflare 规则指南 (docs/cloudflare-cdn-rules.md)](./cloudflare-cdn-rules.md)）。
