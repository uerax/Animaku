> 核心文件：`apps/web/src/player/media/canvas-danmaku.ts`、`apps/web/src/player/media/danmaku-utils.ts`

## 1. 播放器分层架构（自底向上）

```
┌────────────────────────────────────────────────────────┐
│ 4. 播放器控制层 (.kz-player-chrome)                      │
├────────────────────────────────────────────────────────┤
│ 3. 弹幕 Canvas2D 渲染层 (.kz-danmaku-canvas) - z-index:2│
├────────────────────────────────────────────────────────┤
│ 2. Anime4K WebGPU 超分层 (.kz-sr-canvas)    - z-index:1│

```

弹幕层与 Anime4K WebGPU **独立互不干扰**，弹幕画布配置 `pointer-events: none` 与 `contain: strict`，开启独立 GPU 合成图层。

## 2. 核心性能架构与渲染热路径

### 2.1 1:1 Retina 离屏字形位图缓存池 (Glyph Cache)
- **缓存 Key**：`` `${fontPx}|${color}|${text}` ``
- 同一文本仅在首次出现时执行 1 次矢量 `strokeText` 描边与 `fillText` 填充至离屏位图（`OffscreenCanvas`）；
- 渲染热路径每帧 100% 转化为极速 **`ctx.drawImage(glyph)`**，单帧耗时从 8ms 锐减至 $<0.3\text{ms}$（满帧 144Hz 满跑）；
- 配备 LRU 淘汰机制与动态 DPR 缩放保护。

### 2.2 零 GC 内存优化
- **惰性度量 (Lazy Measurement)**：废除全列表预加载 `measureText`，仅在弹幕实际进入发射视窗时按需度量；
- **原地压缩 (In-Place Pruning)**：废除每帧 `running.filter(...)` 造成的数组堆内存分配，采用双指针原地压缩淘汰已飞出屏幕的弹幕。

## 3. 时钟模型与分级漂移治理

### 3.1 纯物理墙上时钟驱动
正常播放下，弹幕渲染位移 $x$ 100% 严格由单调递增的 `performance.now()` 驱动，彻底消除每帧读取视频时间戳导致的高频抖动。

### 3.2 分级漂移治理策略 (Tiered Drift Policy)

```
       0s                  0.5s                   2.0s                  +∞
       ├─────────────────────┼──────────────────────┼────────────────────► |Δt|
            【死区 Zero】          【轻微漂移 EMA】         【硬寻道 Re-anchor】
            完全不修正             一阶低通滤波亚像素校准     判定为用户 Seek
            吸收 24/30fps 抖动    强制单调递增保底 (防回弹)   清空重新排轨对齐
```

1. **死区（$0 \sim 0.5\text{s}$）**：Zero Intervention（完全不修正），吸收所有 24fps/30fps 视频 PTS 抖动与微观掉帧，保持 60/120fps 满帧匀速；
2. **轻微漂移（$0.5\text{s} \sim 2.0\text{s}$）**：采用一阶低通指数平滑滤波器（EMA，$\alpha = 0.05$）亚像素平滑微调，并施加**单向单调保底（Non-decreasing Clamping）**，彻底杜绝时间倒流与 1~2px 横跳抽搐（Rubber-banding）；
3. **硬跳跃（$> 2.0\text{s}$ 或用户 Seek）**：判定为用户大跨度寻道，触发重排轨与对齐；
4. **rVFC 硬件级帧呈现同步**：现代浏览器启用 `requestVideoFrameCallback`，在每一帧视频合成时直接捕获硬件 PTS。

## 4. 交互与降噪模型

- **B 站标准「全量 → 精简 → 关闭」三态循环**（快捷键 `D`）；
- **精简模式去噪**：4.0s 滑动窗口去重聚合并附加 `(xN)` 徽标；
- **同屏密度过载抛弃**：桌面端同屏上限 $12 \sim 24$ 条、移动端 $8 \sim 14$ 条，超额直接丢弃防遮挡；
- **恒定 7.5s 物理屏幕穿越时长**：切倍速时动态连续相位重定，保持真实飞行时间恒定 7.5s；
- **Seekbar 弹幕热力图**：进度条动态绘制蓝光渐变热力波形图，高能名场面一目了然。

---

## 5. 架构决策：为何选用 Canvas 2D + 位图缓存而非 WebGL

1. **文字渲染本质**：浏览器中 WebGL 无法原生绘制 CJK 描边汉字，业界方案依然是「Canvas 2D 栅格化 $\rightarrow$ 上传纹理 $\rightarrow$ GPU 绘制四边形」；
2. **GPU 争抢隔离**：避免在核显上同时运行视频解码 + Anime4K WebGPU + WebGL 导致 GPU 过载掉帧；
3. **极致性价比**：Canvas 2D 位图缓存 + `drawImage` 已将单帧渲染耗时压至 $<0.3\text{ms}$，结构简单健壮，兼具全平台 100% 兼容性。
